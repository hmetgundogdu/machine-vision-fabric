# Stage 12 — Graph primitives, loop, values and live operation (#25, part 1)

**Status: PASS** (macOS arm64 locally; Linux/Windows in CI). Covers the serial executor. The
pipelined executor, joins and per-node parallelism are [stage 13](13.md).

## What was built

- **Primitives** (`mvf_graph::primitive`, `mvf_engine::primitives`):
  - `fork`, `if`, `switch`, `select`, `value` and `loop`, each with a synthesized, validated
    contract;
  - `fork`/`switch` outputs are taken from their edges;
  - `value`/`select` ports are typed by element type and shape, with refined checks between
    primitives;
  - schemas use the .NET JSON Schema subset (`mvf_graph::values`).
- **Loop** (`edges.loop`, `Graph.loop_spec`): `until-exhausted | forever | count`.
  - `forever` rewinds sources (`NodeHandle::rewind`; both builtin sources rewind) and does not
    count the empty pass;
  - `count` ends with `LoopCompleted` and drops the checkpoint;
  - whole-graph pause/resume, including automatic resume.
- **Bindings** (`mvf_engine::bindings`): `.mvf/bindings.json`, read and written with atomic
  replace.
  - Resolution order: `literal` → store → `MVF_BINDING_<KEY>` (transient) → `default`;
  - the pre-pass overlays stored module-binding edits;
  - a `select` with a binding but no criterion fails before cycle 1 with an actionable message.
- **Live operation** at cycle boundaries (`mvf_engine::live`):
  - `set_value` for `value`/`select`, type-checked and persisted;
  - `configure` for bound module fields: live through the worker protocol's `configure`, otherwise
    by reopening the node;
  - `pause`/`resume`;
  - update plans gain `set`, `configure`, `pause` and `resume` steps;
  - `RunReport.live` and `RunReport.iteration` record all of it.
- **On-demand activation**: the node starts the first time it runs. Checkpointed state is handed
  over at activation, and an unactivated node keeps its last state in later epochs.
- **Builtins for the demo twins**:
  - `folder-source` gains `cameraId`, `frameIntervalMs` and rewind;
  - new `dataset-writer` builtin, with the same layout and file names as the .NET
    `mvf.dataset-writer`.
- **Demo twins** in `rust/examples/{inspection,loop,value}-demo`, plus `loop-demo/updates.yaml`
  (pause, value edit, rejected edit, module-binding edit).

Syntax, typing and the deliberate differences from .NET: [graph-primitives.md](../graph-primitives.md).

## Evidence

### Output parity with the .NET engine

`rust/scripts/parity-demos.sh` runs `packages/<demo>` on the .NET engine and the Rust twin on the
Rust runtime:

- same frames;
- the same, unchanged Python modules (`py.invert-transformer`, `py.brightness-classifier`,
  `py.frame-counter`);
- the same cycle count;
- pacing off on both sides.

It then compares every dataset file by logical path and SHA-256, plus the metadata fields that are
not paths or timestamps.

```text
$ SKIP_BUILD=1 CYCLES=40 rust/scripts/parity-demos.sh
demo             .NET files Rust files  result
inspection-demo         100        100  IDENTICAL
loop-demo                40         40  IDENTICAL
value-demo               40         40  IDENTICAL
  selections: pick-one=DEF456 pick-protocol=[ABC123, DEF456] every cycle=True -> MATCH
PARITY PASS (40 cycles per demo, ...)
```

The inspection demo exercises `fork` (five ways), two `switch`es, a `value`, the `forever` loop
(nine rewinds in 40 cycles), a stateful Python counter across rewinds and four writers. File names
such as `000003-sim-cam-1-seq0001.bin` encode each writer's global order, the camera and the
source sequence, so identical names mean identical routing in identical order. The .NET CLI prints
no selections, so the value-demo selections are checked against what `ValueAndSelectGraphTests`
asserts.

## Limits

- No interactive prompt or TUI. An unresolved binding fails the run before cycle 1 (documented
  difference).
- One `loop` per graph (`graph.loop.multiple`), as in .NET. The forward `tick` (loop → head) is not
  wired in either engine.
- The session timestamp in `dataset-writer` directory names is UTC; the .NET writer uses local time.
  Names are compared without the timestamp.
