# Stage 11 — P0.1 parity: checkpoint/restore, backpressure policies, restart policy (#24)

**Status: PASS** (macOS arm64 locally; Linux/Windows in CI)

## What was built (`mvf-engine::recovery`, pipeline `run` and node fields)

| .NET reference | Rust |
|---|---|
| `NodeFailurePolicy` `fail` / `restart` + `Limit` (0 = forever), exponential backoff 500 ms → 5 s, one attempt budget per execution, hard restart (fresh session/model), retry the same inputs | `onError: fail \| skip \| restart` or `{ mode, limit, backoffMs, maxBackoffMs }` with the same defaults and semantics; a failed restart counts as an attempt; cancellation is never retried |
| Role defaults: a faulted source ends the run, a faulted mid-graph node skips its cycle | `run.onError: { sources: fail, nodes: skip }` reproduces them; the Rust default is `fail` for every role (nothing fails silently unless configured) |
| `BackpressurePolicy` `stall` (lossless; in the serial executor an actionable stop) / `drop` (skip, count) | `backpressure: stall \| drop` per node or `run.backpressure`; a full arena is now its own error kind (`Backpressure`), `stall` ends the run with "raise the arena slot count, or set `backpressure: drop`" |
| `CheckpointIntervalCycles`, `CheckpointDirectory`, `FileCheckpointStore`, restore before the first cycle, clear after a clean fully consumed run | `run.checkpoint: { everyCycles, directory }` / `--checkpoint-every`, `--checkpoint-dir`; epochs written to `epoch-<n>.tmp/`, renamed, then published by atomically replacing `CURRENT` (a crash mid-write never yields a mixed epoch); resume restores states and continues cycle numbering; cleared only when the source is exhausted |
| Worker crash → restore the last in-memory checkpoint into the restarted worker | restart restores the node's latest captured state; workers export/import through protocol `checkpoint`/`restore` |

Also: source cursors (`synthetic-source`, `folder-source`) are checkpointed, so a resumed run
continues the stream; workers now also support **stateful live replacement** (state moved from the
old to the new process through the same messages). Run reports gain `recoveries`,
`resumedFromCycle` and per-node `restarts`, `failuresSkipped`, `dropped`.

## Semantics to know

- Recovery from a checkpoint rolls state back to the last epoch: with `everyCycles: N > 1`, work
  between the epoch and the failure is redone from that state (the .NET engine behaves the same).
  `everyCycles: 1` makes restarts exact at the cost of a capture per cycle.
- A restarted node gets a new generation number (fencing), like a promoted replacement.
- Checkpoints capture only nodes that export state; stateless nodes need nothing.
- The .NET pipelined executor's epoch-barrier checkpointing applies to concurrent stages; the Rust
  executor is serial, so every cycle boundary is already quiesced.
