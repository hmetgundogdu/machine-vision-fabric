## What was built

- **`mvf-rs import <package | pipeline.json> [--out F] [--modules DIR] [--force]`**
  (`crates/mvf-cli/src/import.rs`). It writes `pipeline.yaml` next to the legacy file, so relative
  paths keep their meaning, then validates it on this host.
- **The conversion** (the table in the [migration guide](../migration-guide.md)):
  - **Ids:** become valid contract ids, and edges follow.
  - **Modules:** `mvf.folder-source` and `mvf.dataset-writer` become builtins, with the .NET
    simulator's camera id. Other modules stay modules and must resolve to a `node.yaml`.
  - **Edges:** sorted into data, control or loop by the contracts' port channels.
  - **Failure policy:** `run.onError: { sources: fail, nodes: skip }` reproduces what the .NET
    engine does.
- **What the importer refuses or reports:**
  - **Exit 2, nothing written:** an unknown field, an unknown primitive, a port-less edge that
    does not close into a `loop`, two ids that collide after conversion, and an existing output
    without `--force`.
  - **Exit 1, file written:** a module without a contract here, for example a .NET in-process
    camera. Every one is named, with what to do.
- **The YAML writer:**
  - **Values:** block structure with JSON-quoted scalars, valid YAML 1.2 that the strict
    pipeline parser reads back unchanged.
  - **Keys:** awkward keys (`true`, `on`, `a: b`) are quoted.
  - **Order:** keys follow reading order (`id` first, `nodes` before `edges`). Display names and
    the legacy version go into the header comment.
- **Parity script:** `RUST_SOURCE=import rust/scripts/parity-demos.sh` converts each legacy
  package with the importer instead of using the hand-written Rust twin.
- **Release:**
  - **Version:** the workspace is `1.1.0`, and `mvf-rs --version` says so.
  - **Workflow:** `release.yml` gains a `rust-runtime` job that builds `mvf-rs`, `mvf-remote` and
    `mvf-display-host` for three platforms and zips them with the license. A tag that does not
    match `rust/Cargo.toml` fails the job. The legacy CLI and SDK jobs are unchanged.
- **#34, the non-destructive part:**
  - [migration-guide.md](../migration-guide.md): install, convert, missing modules, bindings,
    command mapping, validation, rollback, known differences (no TUI or prompts, egress not
    ported).
  - [legacy-retirement.md](../legacy-retirement.md): an inventory of every .NET project
    (retain / migrate / remove after the gate) and the gate's state.

| `import_converts_a_legacy_package_and_names_what_it_cannot_carry_over` (`crates/mvf-cli/tests/cli.rs`) | `inspection-demo` converts (4 renames, builtins mapped, 13 nodes and 12 data edges valid, Python modules resolved); no overwrite without `--force`; the converted `loop-demo` runs to its cycle limit and writes a dataset; `py-invert-demo` names the Cognex camera MISSING (exit 1); four malformed documents are refused with exit 2 and nothing written |

Parity with the .NET engine, using converted legacy packages (macOS, 24 cycles per demo, every
dataset file by SHA-256 plus per-frame metadata):

```text
$ RUST_SOURCE=import DEMOS="inspection-demo loop-demo value-demo multilang-demo" rust/scripts/parity-demos.sh
inspection-demo          60         60  IDENTICAL
loop-demo                24         24  IDENTICAL
value-demo               24         24  IDENTICAL
multilang-demo            8          8  IDENTICAL
PARITY PASS (24 cycles per demo, Rust mode serial, Rust pipelines from import, …)
```

The same with `RUST_MODE=pipelined`: PASS, all four IDENTICAL. The twin mode
(`RUST_SOURCE=twin`, the default) still passes, including the value-demo selection checks.

- **`multilang-demo`** has no Rust twin, so this is new coverage. It has no loop, so both runtimes
  end when its folder runs dry, which the script now accepts.
- **The other three packages** all use a .NET in-process camera (Cognex or the synthetic camera),
  which the importer correctly reports as MISSING: `belt-sim-demo`, `py-brightness-demo` and
  `py-invert-demo`.

## Limits

- **Only the legacy fields the repository's packages use are known** (`name`, `version`,
  `description`, `nodes[id, primitive, module, displayName, config, bindings]`,
  `edges[from, to]`). Anything else is refused, not guessed.
- **.NET in-process modules are not converted.** They need a worker (`Mvf.Worker`) and a
  `node.yaml`.
- **Egress is not ported.**
- **Real-pipeline validation on edge hardware** (Rotary) is the maintainer's next step, and the
  removal gate of #34 depends on it.
