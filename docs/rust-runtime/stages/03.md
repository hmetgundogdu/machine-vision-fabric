# Stage 03 — Execution backend API and lifecycle supervisor (#13)

**Status: PASS** (macOS arm64 locally with Python 3.9.6; Linux/Windows with Python 3.12 in CI)

## What was built

- **Backend API** (`mvf-engine::backend`): `ExecutionBackend { capabilities(), instantiate() }`
  produces runtime-owned `NodeHandle`s (`start` = activation + readiness within a budget,
  `execute` with cycle id / generation / cancellation / deadline, `drain`, idempotent `stop`,
  versioned state export/import). `BackendRegistry` negotiates (#11) and instantiates; anything
  the negotiation rejects fails closed at build with `Unsupported`.
- **In-process backend**: trusted builtins; isolation `none`, cooperative cancellation, no
  enforceable termination. Rust panics are caught at the backend boundary
  (`NodeErrorKind::Panicked`) and the handle is poisoned.
- **`mvf-worker`** — supervised local stdio worker backend speaking the **existing protocol v1**
  (`protocol/README.md`) so the existing Python SDK modules run unchanged:
  - spawn once at `start` (never per frame); `hello` (+ `ready` after async warmup) within
    `readinessTimeoutMs`; protocol version and advertised capability checked against the
    contract's ports (fail closed); `configure` sent only to workers that advertise it;
  - `execute` bounded by `executeTimeoutMs` and the cancellation token — on timeout or
    cancellation the process is **killed** (enforceable), not asked;
  - exit classification: managed `error` reply (`Failed`) vs process exit with code or Unix
    signal (`ProcessExited`, e.g. `SIGSEGV`);
  - graceful stop: `shutdown`, close stdin, wait `drainTimeoutMs`, then kill (`Forced`); every
    handle kills **and reaps** its child on drop;
  - structured logs: worker `log` messages, forwarded stderr and supervisor lifecycle events go
    to `HostServices.logs` (CLI: stderr, `--json` as JSON lines); non-protocol stdout is logged,
    overlong lines (> 1 MiB) are discarded without buffering;
  - output validation: a worker may only return the output slot it was given (foreign offsets are
    `Protocol` errors) and its header is validated before use (`InvalidOutput`); the slot is
    reclaimed on rejection.
- **`mvf-memory`**: descriptor codec byte-compatible with `PayloadDescriptor` (192-byte header)
  and the engine-owned file-backed arena (RAII reservations, reference-counted generation-checked
  leases). In this slice the worker uses it in **copy mode**: the input frame is copied into an
  arena slot once and the worker's output is copied out once. Zero-copy routing is slice 04.
- **Module resolution**: pipelines may reference installed modules by id (`module: py.…`), the
  counterpart of the .NET `"module"` references; contracts live in `modules/<dir>/node.yaml`
  (added for `py-invert-transformer`, `py-brightness-classifier`, `py-warmup-classifier`,
  `py-brightness-analyzer` — their code and `module.json` are untouched).
- CLI: worker backend registered; `--modules` / `MVF_MODULE_PATH` / auto-discovery of the
  nearest `modules/`; example `rust/examples/python-worker`.

## Capability matrix (as advertised by `mvf-rs host`)

| | in-process | worker |
|---|---|---|
| isolation | `none` (engine failure domain) | `process` (crash/hang contained; **not** a security boundary) |
| cancellation | cooperative | enforceable (process kill) |
| enforceable termination | no | yes |
| resource limits enforced | none | none |
| zero-copy domains | host (`Arc` sharing) | none yet (copy in/out; slice 04) |
| replacement | stateless, stateful | stateless |

A contract requiring `isolation.minimum: sandbox` or `resources.enforcement: required` is
rejected for both (`unsupported_security_and_limit_requests_fail_closed_at_build`).

| Capabilities distinguish cooperative vs enforceable cancellation, trusted in-process vs isolation | PASS | Matrix above; `mvf-engine/tests/executor.rs::cooperative_cancellation_reaches_a_stalled_node` vs `cancellation_is_enforced_by_terminating_the_process` |

## Limitations

- ~~Restart-on-crash policy is not ported~~: resolved in [stage 11](11.md) (`onError: restart`).
- ~~If the host is killed with SIGKILL, children are not killed~~: resolved in [stage 14](14.md)
  (Linux `PR_SET_PDEATHSIG`, Windows Job Objects). macOS still relies on the SDKs' stdin-EOF exit.
- ~~There is no warm pool~~: resolved in [stage 14](14.md) (`MVF_WARM_SPARES`).
- Protocol v1 supports one `frame` input; contracts asking for more fail at build.
- Unsafe code: `mvf-memory/src/arena.rs` (`Send`/`Sync` for the arena, raw slot views, unmapping
  before delete). Audit: see the module docs; ownership rules make in-process aliasing impossible,
  the cross-process trust assumption is documented and covered in stage 04.
