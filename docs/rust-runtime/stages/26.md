## What was built

- **Engine.** `Observer::wants_outputs(node)` and `Observer::outputs(cycle, node, outputs)` let
  an observer see a node's output values in the serial executor. They are asked per executed
  node and default to "no". The values are shared leases, not copies. `Tee` forwards both.
- **Previews** (`mvf_management::preview`):
  - **Opt-in:** only nodes named with `mvf-rs run --manage --preview NODE` can be previewed, only
    by the new `previewer` role or by an operator, and every opening is audited.
  - **Caps:** at most 2 samples/s per node and at most 160×120 pixels (nearest-neighbour
    downscale), with a per-viewer byte budget of 256 KiB/s. A preview over budget is skipped,
    not queued.
  - **Sampling:** the engine hands a shared lease to one preview thread through a single-slot
    queue (`try_send`, so it never waits). The thread drops the lease as soon as it has
    downscaled.
  - **Encoding:** PNG (8-bit grey, RGB or RGBA; uncompressed deflate, CRC-32 and Adler-32 written
    here, no codec dependency), base64 in the JSON line. Other payloads say why they cannot be
    shown.
  - **Nothing retained:** only the latest preview per node, in memory.
- **Package upload** (`mvf_management::upload`, `--allow-uploads`, operator only):
  - **Transfer:** chunked, resumable through `upload-status`, and SHA-256 checked when the last
    byte arrives and again at staging. A chunk the runtime already has is a duplicate and is
    not rewritten; a gap is refused with the expected offset.
  - **Confined:** names (no `..`, no absolute paths, nothing hidden) and sizes (256 MiB per file,
    1 GiB and 64 files per package).
  - **Staging:** the `stage` command stages the package with one atomic rename into
    `<pipeline dir>/.mvf/staged/<package>`, with a manifest. A staged package is immutable;
    re-uploading it is a no-op.
  - **Activation** is the ordinary `replace` naming `.mvf/staged/<package>/node.yaml`, so
    validation, probation and `rollback` are the engine's own.
  - `upload_dir` is the client side: it resumes each file from what the runtime has, then
    stages. The local CLI, the remote CLI and the tests all use it.
- **Relay:** `preview` needs a previewer and streams like `subscribe`. `upload` and
  `upload-status` need an operator, whose request lines may be 1 MiB (also on the local
  endpoint). Every refusal is logged by the relay.
- **CLIs:**
  - `mvf-rs run --manage --preview NODE --allow-uploads`;
  - `mvf-rs manage preview --node N --count K --out DIR` saves PNGs;
  - `mvf-rs manage upload --package P DIR` prints the staged contract;
  - `mvf-remote preview|upload` do the same through the relay;
  - `mvf-remote pki issue --role previewer`.

### Measurements (`MVF_MANAGE_BENCH=1 cargo test --release -p mvf-management --test part3 bench -- --nocapture`)

| | macOS | Linux VM |
|---|---|---|
| 50k cycles of 64×48 RGB, previews off / on | 10.1–10.8 / 10.3 µs/cycle | 11.55–11.66 / 11.73–11.74 µs/cycle |
| one preview of 1280×960 RGB → 160×120 (preview thread) | 0.70 ms, 77 KB | 0.58 ms, 77 KB |
| 32 MiB upload, local endpoint, 512 KiB chunks, digests and staging | 81 MiB/s | 78 MiB/s |

- **Previews on the engine thread:** within noise on macOS, and at most about 0.2 µs per cycle on
  the VM. The rendering cost is on the preview thread.
- **Base64:** a 160×120 RGB preview is 57.6 kB of pixels and 77 kB on the wire. That is the
  measured cost of keeping one JSON protocol.

## Limits

- **Package signatures** came after this stage, in [stage 27](27.md).
- **Previews come from the serial executor only.** The pipelined executor never asks for
  outputs.
- **Previews are uncompressed PNG.** Small at 160×120, wasteful at higher caps. A deflate or JPEG
  encoder would trade CPU and a dependency for bandwidth.
- **An upload's chunks are base64 in JSON** (about 33 % overhead) and capped at about 768 KiB of
  data per line, under the 1 MiB line limit.
- **Staged packages are kept** until removed by hand. There is no garbage collection of old
  versions yet.
- **No measurements on industrial edge hardware.**
