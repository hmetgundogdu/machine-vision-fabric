# Stage 08 — Daemonless OCI execution backend and device capability policy (#18)

**Status: PASS for Linux OCI execution · BLOCKED for GPU device grants and Windows (HCS)**

## What was built (`rust/crates/mvf-container`)

- **Backend selection (ADR)**: a low-level OCI runtime — `runc` (tested: 1.1.5 from Debian
  bookworm) or `crun`, found on `PATH` or via `MVF_OCI_RUNTIME` — driven directly by MVF with a
  generated `config.json` bundle. No Docker Engine, containerd or any daemon. Rationale: these are
  the proven, audited implementations Podman/Docker themselves use; re-implementing namespace and
  cgroup setup in-process would add risk without benefit. Youki (Rust) is a drop-in candidate for
  the same seam.
- **An OCI node is a worker whose launcher is the runtime**: `mvf-worker` gained a `Launcher`
  trait (`prepare(arena) -> LaunchSpec`, `cleanup()`); the container's stdio *is* the MVF protocol
  and the engine arena is bind-mounted at `/mvf/arena`, so readiness, deadlines, kill, exit
  classification, logs and **zero-copy** hand-off are identical to local workers. Cleanup always
  runs `runc delete --force` and removes the bundle (after stop, failure, timeout, cancellation and
  `Drop`).
- **Default-deny sandbox** (`spec.rs`): new pid/mount/ipc/uts/cgroup/**network** namespaces; a user
  namespace (container 0–65535 → host 100000–165535) when the host runs as root, with the rootfs
  cache owned by the mapped root; all capabilities dropped, `noNewPrivileges`; read-only root;
  size-limited tmpfs `/tmp`, `/dev`, `/dev/shm`; read-only namespaced `/sys` and cgroupfs; masked
  and read-only `/proc` paths; seccomp denylist (mount, namespaces, modules, kexec, keyrings, bpf,
  ptrace, …); device cgroup default deny; memory/cpu/pids cgroup limits; the arena is the only host
  path mounted (`noexec,nosuid,nodev`). Image user (numeric or named via the rootfs
  `/etc/passwd`/`/etc/group`), entrypoint, cmd, env and working directory are honoured.
- **Capability negotiation**: the backend reports isolation `sandbox` only when the runtime has
  seccomp support, limits only when cgroup v2 controllers are writable (root), network policy
  `none` only, grantable devices = character/block devices present on the host, CDI devices =
  none. New contract section `spec.permissions` (`network`, `devices[{path, access}]`,
  `cdiDevices`) — default deny, unavailable grants rejected at build
  (`negotiation.permission-unsupported`, `negotiation.device-unavailable`,
  `negotiation.cdi-device-unavailable`).
- **Generic workloads**: `run_workload` runs an image's own entrypoint/cmd (or arguments) to
  completion under the same sandbox — the "arbitrary image" compatibility level, distinct from
  typed graph nodes.
- **Packaging**: `mvf-rs image package` builds an OCI-profile node image (base image + SDK +
  module + `/mvf/node.yaml`, label `dev.mvf.node.contract`) and writes a contract pinned to its
  digest (`isolation.minimum: sandbox`, backend `oci`).
- On non-Linux hosts the backend is not registered; contracts requiring it are rejected.

What those tests assert, inside the sandbox: `CapEff`/`CapBnd` = 0, `NoNewPrivs: 1`,
`Seccomp: 2`, `uid_map 0 100000 65536`, own pid namespace (`pid1: sh`), no routed interface and an
empty routing table, `wget` to the internet fails, `mount` fails, rootfs read-only but `/tmp`
writable, no host block devices, `memory.max = 33554432`, `pids.max = 16`, `cpu.max = 50000 100000`,
a 96 MiB buffer under 32 MiB is OOM-killed, forks beyond `pids: 8` fail, a read-only device grant
is visible but not writable and absent without the grant, a crashed node is reported as
`ProcessExited` with its exit code and leaves no container or bundle behind. The Python module runs
unchanged as a typed node: 20 frames, outputs identical to the Rust inversion, `copiesIn = 0`,
`copiesOut = 0`, 20 zero-copy hand-offs. Live replacement of an OCI workload: candidate prepared in
**4.5 s** (rootfs unpack + chown + container start + Python start) while v1 kept running, cut-over
**106 µs**; a crashing OCI candidate was rolled back (6 µs) and its cycle replayed, 1500/1500
cycles exactly once.

## Prerequisites and limits

| | |
|---|---|
| OS | Linux with namespaces and cgroup v2. Tested: linuxkit 6.10 aarch64 (Docker Desktop VM). |
| Privileges | root for cgroup limits and the user namespace. Rootless runc is **not exercised**; without root the backend reports no enforceable limits, so `enforcement: required` contracts are rejected. |
| Runtime | `runc` (tested 1.1.5) or `crun` with libseccomp. |
| Architectures | images must match the host (`linux/arm64` tested); no emulation. |
| **Windows** | **BLOCKED**: Windows containers need the Host Compute Service (hcsshim) and Windows images; Linux images on Windows need WSL2. Windows-first path: run this backend inside WSL2 (same code), and evaluate an HCS backend behind the same `Launcher` seam. Not implemented or tested. |
| **GPU device grant** | **BLOCKED**: no GPU is exposed in the Linux VM and CDI injection is not implemented; `cdiDevices` requests are rejected (`unavailable_devices_and_cdi_gpus_are_rejected_before_start`). Plain `/dev/dri/*` or `/dev/nvidia*` nodes would go through the tested device-grant path, but no such device existed to test. |

## Threat model (what the sandbox does and does not stop)

- **Protects against** a malicious or buggy node image: reaching the network, other host files,
  host devices, gaining capabilities or privileges via setuid, mounting, loading kernel modules,
  using namespace/keyring/bpf/ptrace syscalls, exhausting host memory/pids beyond its limits,
  surviving its own stop.
- **Does not protect against**: kernel vulnerabilities in allowed syscalls (denylist, not
  allowlist; no AppArmor/SELinux profile); reading or writing **other slots of the shared arena**
  (the shared arena is mapped read-write — see stage 04; a node with `memory.arena: private` gets an
  arena of its own since [stage 14](14.md)); CPU side channels; a compromised host or MVF
  engine (the runtime runs as root; container root is remapped).
- The rootfs cache is shared read-only between instances of the same image.
