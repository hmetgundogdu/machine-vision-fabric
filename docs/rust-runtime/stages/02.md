# Stage 02 — Strict typed graph and deterministic CPU executor (#12)

**Status: PASS** (macOS arm64 locally; Windows/Linux via CI)

## What was built

- **`mvf-graph`** (pure, no host dependencies): pipeline document (`kind: Pipeline`) parsed by the
  strict YAML loader; contract resolution through a `ContractResolver`; validation reporting every
  issue with a stable code; deterministic topological order (Kahn, ties by declaration index) with
  a concrete cycle path on failure. **Data and control edges are separate lists**
  (`spec.edges.data`, `spec.edges.control`) — a single untyped `edges:` list is rejected by schema.
- **`mvf-engine`**:
  - typed runtime values (`frame`, `tensor`, `classification`, `json`, `value`, `signal`) with a
    `Descriptor` (media/element/shape, C-contiguous) checked against byte length; fan-out shares
    payload bytes (`Arc`), never copies them;
  - `NodeHandle` — one lifecycle interface (`start`/`execute`/`drain`/`stop`/state export-import)
    for every backend, plus a minimal `ExecutionBackend` seam with negotiation (fleshed out in #13);
  - trusted in-process builtins with **embedded YAML contracts** validated like any external
    contract: `synthetic-source`, `invert`, `passthrough`, `brightness-gate`, `record`, `fault`
    (test fixture);
  - the serial executor (single scheduling authority) — semantics in the module docs and below;
  - `HostResolver`: builtins + contract files confined to the pipeline package directory.
- **`mvf-cli`** → `mvf-rs` binary: `contract`, `validate`, `run [--json] [--max-cycles N]`, `host`.
  Ctrl+C cancels at the next cycle boundary. Exit codes 0/1/2.
- Examples: `rust/examples/basic` (source → invert → sink), `rust/examples/gated` (control edge).

## Supported semantics (exactly)

| Semantics | Behaviour |
|---|---|
| Cycle ids | 1-based, monotonic, one per completed cycle. |
| Order in a cycle | Sources first (declaration order), then topological order. |
| Run condition | Every required data input present **and** every connected control input present and `true`. Else skipped; outputs absent. |
| Absence | Propagates: a consumer of a skipped node's output is skipped (required) or runs without it (optional). |
| Fan-out | One output → many inputs; the value (and payload `Arc`) is shared. |
| Fan-in | One edge per input port; implicit joins are rejected (`graph.input.multiple-edges`). |
| Source exhaustion | Ends the run before any non-source runs in that cycle (`source-exhausted`). |
| Failure | `fail` policy: run ends with node, cycle and classified cause (`failed`, `panicked`, `invalid-output`, …). |
| Cancellation | Checked at cycle boundaries (cycles are atomic); nodes may observe the token cooperatively. |
| Bounded input | `spec.run.maxCycles` or `--max-cycles` (`cycle-limit`); `0` is rejected. |
| Runtime typing | Every emitted value is re-checked against the declared output port and type. |

### Inventory for later parity (not supported in this slice)

Fork/if/switch/select/value/loop primitives, joins (pipelined executor), per-node parallelism,
activation `on-demand`, node failure policy `restart`, backpressure, epoch checkpoint/restore and
live `configure`. All rejected or absent rather than approximated; tracked in
[../parity-matrix.md](../parity-matrix.md).

## Limitations

- Serial only; no parallel scheduler (out of scope).
- `value` scalars and `tensor` ports exist in the type system but no builtin produces them yet.
- Unsafe code: none.
