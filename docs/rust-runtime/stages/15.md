# Stage 15 — OCI hardening: layer cache, seccomp allowlist, LSM option (#28, part 2)

**Status: PASS**, with LSM enforcement **BLOCKED** on the test host: its kernel (linuxkit 6.10)
has neither AppArmor nor SELinux. Measured on the Linux test host: privileged
`debian:bookworm-slim` with `runc` 1.1.5, aarch64, no Python and no Docker daemon inside.

## What was built

| Item | Implementation |
|---|---|
| **Layer-level rootfs cache** (`mvf_oci::LayerCache`) | Each layer is unpacked **once** into `<state>/layers[-u<id>]/<diff_id>/rootfs`, verified against its `diff_id`, and published atomically. A layer that fails verification is never published. Whiteouts and hard links into lower layers are recorded in `layer.json` rather than applied. An image's rootfs is composed by replaying its layers in order: links and whiteouts first, then entries. Regular files are **hard-linked**, so no bytes are copied; directories and symlinks are recreated. The replay uses `unpack`'s securejoin resolution, so writes through lower-layer symlinks land where a full unpack puts them. With a user namespace, ownership is set once per cached layer. The composed rootfs is mounted read-only, so the shared inodes cannot be modified. The composed tree is still cached per manifest, as before. |
| **Seccomp allowlist** (`mvf_container::seccomp`) | Contract `isolation.syscalls: allowlist` (requires `minimum: sandbox`), or for the whole host `MVF_OCI_SECCOMP=allowlist` / `OciBackend::with_syscall_allowlist`. The default action is EPERM. Allowed syscalls come from Docker's default profile, vendored unchanged (moby `docker-v29.10.1`, Apache-2.0, see `src/seccomp/NOTICE`). The profile is specialised for a container with no capabilities on the host architecture, with argument filters and `clone3 → ENOSYS` kept, **minus our denylist**, so the stricter of the two policies applies. The denylist stays the default. |
| **LSM option** | `MVF_OCI_APPARMOR_PROFILE` (used when the kernel has AppArmor enabled) or `MVF_OCI_SELINUX_LABEL` (when SELinux is enabled) sets `process.apparmorProfile` / `process.selinuxLabel`. The profile must already be loaded on the host, as with Docker's `--security-opt`. The backend advertises it as a grant (`apparmor:<p>` / `selinux:<l>`). Contract `isolation.lsm: required` (requires `minimum: sandbox`) is negotiated fail-closed: `negotiation.lsm-unavailable` on hosts without one. |

## Limits

- **Cache garbage collection.** There is none: cached layers stay until the state directory is
  cleaned. The cache needs the layers and the composed rootfs on one filesystem; across
  filesystems, files are copied instead of linked (counted as `copied`).
- **Allowlist and future runtimes.** The allowlist is Docker's syscall set for a container without
  capabilities. A workload that needs a syscall Docker does not allow, such as `io_uring`, fails
  under it, and that is the intended trade-off. `minKernel` conditions are assumed to hold
  (kernel ≥ 4.8).
- **LSM.** MVF does not ship or load profiles. Enforcement is untested here until a host with
  AppArmor or SELinux is available.
