# Stage 06 — Gate A: runnable foundation demo, regression tests and ADR (#16)

**Status: PASS** — see [../gate-a-report.md](../gate-a-report.md) and
[../gate-a-report.json](../gate-a-report.json).

## What was built

- **One command for the gate**: `rust/scripts/gate-a.sh` (and `gate-a.ps1` for Windows) runs fmt,
  clippy, builds the C++ SDK example if CMake is present, runs the full test suite and the
  self-verifying demo.
- **Self-verifying demo**: `mvf-rs run … --verify [--expect-promotions N] [--expect-rollbacks N]`
  checks a normal end, that every completed cycle reached each recording sink exactly once and in
  order (frame sequence = cycle id), that no arena slot leaked, and the expected number of
  promotions/rollbacks; exit code 3 on failure, `{"verify": …}` JSON with `--json`.
- **Demo** `rust/examples/live-update`: synthetic camera (arena) → `proc` (v1 in-process Rust
  invert → v2 Python worker invert, warmed while running → v3 faulty candidate rolled back to v2 and
  the failed cycle replayed) → Python brightness classifier → recorder; 120 cycles, zero transfer
  copies.
- **Regression tests**: `gate_a_demo_verifies_ordered_output_replacement_and_rollback` and
  `verify_fails_with_exit_code_3_when_expectations_are_not_met` in `mvf-cli/tests/cli.rs`, on top
  of the 108 earlier tests.
- **Baseline procedure** `rust/scripts/bench-baseline.sh` against the unchanged .NET engine:
  Rust `folder-source` builtin (counterpart of `mvf.folder-source`), `node.yaml` for the existing
  `py-bench-touch`/`py-bench-numpy` modules, and Rust twins of the .NET bench pipelines in
  `packages/bench/rust-pipeline-*.yaml`. Reports start-up and cycle time separately
  (`startupMs`, `cyclesMs` in `RunReport`).
- **ADR**: [../adr-0001-gate-a-foundation.md](../adr-0001-gate-a-foundation.md).
