# Stage 14 — Worker hardening: orphans, warm pool, private arenas (#28, part 1)

**Status: PASS.** Orphan prevention is verified on Linux (local container) and Windows
(`windows-latest` CI). macOS has no kernel mechanism (documented). Part 2,
for OCI (layer cache, seccomp allowlist, LSM), is [stage 15](15.md).

## What was built (`mvf-worker`)

| Item | Implementation |
|---|---|
| **Orphan prevention** (`spawner`) | Every worker process is spawned by one process-wide spawner thread. **Linux**: `PR_SET_PDEATHSIG(SIGKILL)` in `pre_exec`. The signal is tied to the forking *thread*, which is why one long-lived thread does all spawning: workers are started from candidate-preparation, pipelined-stage and restart threads that end. A child whose host died before the signal was armed exits immediately (`getppid` check). **Windows**: every child joins one process-wide Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, whose handle is never closed, so the OS kills the members when the host ends. **macOS**: no kernel mechanism; children still rely on the SDKs' exit on stdin EOF. |
| **Warm worker pool** (`pool`; parity with `WarmWorkerPool`) | `MVF_WARM_SPARES=n` or `WorkerBackend::with_warm_spares(n)`, default 0 as in .NET. Each node gets a pool of pre-handshaked spares: `hello`, plus `ready` after warmup. The pool is shared by all generations of the node, so a restart or reopen takes a spare instantly while the pool refills in the background. An empty pool falls back to a cold spawn. A spare that died while idle is discarded. Config and state are applied after acquisition, as after a cold spawn. When the last generation drops the pool, its idle spares are killed. Applies to process launchers (Python/executable); OCI nodes start cold. |
| **Private arenas** | Contract `spec.memory.arena: shared \| private`, or for the whole host `MVF_ISOLATE_ARENAS=1` / `WorkerBackend::with_isolated_arenas(true)`. A private node's process maps an arena file of its own: the engine's slot size, `MVF_PRIVATE_ARENA_SLOTS` slots (default 8). Inputs from anywhere else are copied in, one counted copy (`private arena: copiesIn=…` at stop). Outputs live in the private arena and travel downstream by lease, and a downstream worker copies them into its own arena. Negotiation is fail-closed: the backend must advertise `privateArenas`; worker and OCI do, in-process and compute do not (`negotiation.private-arena-unsupported`). `zeroCopy: required` together with `arena: private` is a contract error (`contract.memory.private-arena-copies`). OCI nodes mount their private arena the same way they mount the shared one. |

## Semantics and limits

- **PDEATHSIG covers only direct children.** A worker that forks its own children must arrange
  their death itself. On Windows, job membership covers the whole process tree.
- **Windows race.** `std` cannot spawn a child suspended, so if the host dies between `spawn` and
  `AssignProcessToJobObject`, that child can escape.
- **Cost of private arenas.** Each private arena reserves `slotSize × slots` in its backing
  directory (`/dev/shm` on Linux). Isolation costs one copy per worker input that did not come from
  the worker itself. Fan-out from one producer to N private workers costs N copies.
- **Warm spares** use CPU and memory while idle (the model is loaded). The pool does not shrink.
