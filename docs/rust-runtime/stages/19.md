## What changed

- **Surfaces for OCI nodes.** A `managed-surface` OCI node gets its surfaces from the engine's
  registry, the same files for every generation.
  - Each surface and its writer lock are bind-mounted (`noexec,nosuid,nodev`) into a private
    tmpfs at `/mvf/display`, owned by the mapped container root.
  - `MVF_DISPLAY_SURFACES` points there.
  - Nothing else of the display is mounted: no run directory, no host lock, no other node's
    surface, no X11 or Wayland socket.
- **OCI negotiation.** OCI capabilities offer `managed_surface: true`, `native: false`. A required
  `native` node is rejected; an optional one runs headless and logs why.
- **The lock is held per present.**
  - The writer lock now covers one present or one input drain, never the time between frames.
  - The frame sequence and the input tail live in the surface, so any generation continues them.
  - The window follows a live replacement at the candidate's first frame, returns on rollback and
    survives a crash restart, all without an engine hook.
  - A writer that finds the lock busy gets `standby` immediately, never a wait.
- **SDKs:** the Python `Surface.sequence` and the Rust `SurfaceWriter::sequence()` expose the
  surface's frame sequence. The worker backend gained `WorkerBackend::with_python_sdk`, used by
  tests that build modules outside the repository.

### Window across live replacement and rollback (portable: `crates/mvf-worker/tests/display.rs`)

`the_window_follows_live_replacement_and_rollback`:
- A presenter is replaced v1 → v2 (probation 20 cycles), then v2 → v3. v3 crashes on its 20th
  frame during probation and is rolled back to v2.
- One host reader shows, in order, `[v1, v2, v3, v2]` in one strictly increasing sequence. 260 of
  260 frames are presented, none rejected.
- The rollback re-ran the failed cycle, so no status was lost or doubled.
- Cut-overs: 23, 20 and 35 µs (macOS). The window is never reopened.

## Evaluated, not done

| Combination | Finding | Status |
|---|---|---|
| Native windows for OCI nodes on **X11** | An X11 client can read every window and inject input into all of them. There is no per-client isolation to grant. | **Never granted** |
| Native windows for OCI nodes on **Wayland** | Bind-mounting the compositor socket works technically: Wayland isolates clients from each other. But it gives the node full compositor-client access, and the socket's owner must match the container's mapped uid. The operator would have to grant that explicitly. | **Design-gated** (negotiation rejects; `required: false` runs headless) |
| Windows Session 0 service engine → host in the user session | Windows file locks and file mappings work across sessions. The rendezvous directory needs an ACL that admits the interactive user, and the host must be started in the user session (Task Scheduler / autostart). | **BLOCKED**: no Windows service host to test on |
| Windows, Linux OCI in WSL2 | Engine and host both inside WSL2 is the Linux path: WSLg's Wayland would show the windows. A host on the Windows side cannot map WSL2 files coherently (9p), so a copy transport would be needed. | **BLOCKED**: no Windows/WSL2 machine |
| macOS, Linux OCI in a VM | virtio-fs without DAX shares no pages, so a guest → host transport is needed (vsock copy or encoded frames). | **BLOCKED**: no VM in scope |
| GPU shared textures (D3D, DMA-BUF, IOSurface) | — | P4, not started |

## Limits

- **Access with a root engine.** With rooted OCI the surfaces are owned by the container's mapped
  uid (mode 0600). A display host running as the desktop user then needs access: run the engine
  as that user for worker nodes, or grant an ACL on the run directory. Rootless OCI is #27. In
  the tests, engine and host run as root.
- **The writer pid is namespace-local** (1 in every container): informational only.
- Part 1 limits still apply: polling host, 2 s attach staleness, CPU frames only, no fullscreen or
  clipboard.
