# Stage 13 — Pipelined executor: joins, per-node parallelism, epoch barriers (#25, part 2)

**Status: PASS** (macOS arm64 locally; Linux/Windows in CI)

## What was built (`mvf_engine::pipelined`, `RunOptions::pipelined`, `mvf-rs run --mode pipelined`)

| .NET `PipelinedGraphExecutor` | Rust |
|---|---|
| One task per node, bounded per-edge queues (`--queue`, default 2) | One thread per stage with inbound edges; bounded `sync_channel` per edge (`--queue`, default 2). The engine thread is the **driver**: it runs every node without inbound edges (sources first, then `value`s) once per cycle, like the serial executor. |
| Void markers: one message per edge per cycle; a join reads one from each, cycle ids must agree | Same invariant and the same loud failure on a mismatch. Gating (required data, control present and true) reuses the serial rules, so an untaken `switch` branch or a closed `if` never stalls a join. |
| Backpressure: a full queue blocks the producer | Same. A full **arena** under `stall` now waits (up to 30 s) for downstream to release a slot instead of stopping; `drop` skips the cycle. |
| Epoch barrier: stop feeding, drain at the leaves, capture with nothing in flight | The run proceeds in **segments**. At every quiesce point the driver stops feeding, stages drain and join, and the engine is back at a serial cycle boundary. Quiesce points: checkpoint epochs, control commands, pause, end. Capture, resume and the `CURRENT` publish are the stage-11 code, unchanged. |
| `parallelism: N` up to the module's `maxParallelism`; N instances in N processes; re-order buffer | Contract `spec.execution.maxParallelism` (rejected above 1 for `stateful` nodes) plus node `parallelism`; `graph.node.invalid-parallelism` above the ceiling. N instances pull from a shared work queue, and results are re-ordered by cycle before routing. A failing instance restarts on its own under the node's `onError`. |
| Graph-derived arena slots: `1 + Σ workers (queue + 3 × instances)` (min 8) | `pipelined::arena_slots_for`: the same rule, plus arena-publishing sources. The CLI applies it unless `--arena-slots` is given. |
| Rejects `loop`, `value`, `select`, on-demand nodes and multi-producer ports | **Supports** `loop` (`forever` rewinds inline in the driver, `count`, pause at a boundary), `value`/`select` (the driver paces `value`s per cycle) and on-demand nodes (lazy start inside the stage). Multi-producer ports are rejected by the graph (`graph.input.multiple-edges`). |
| — | Live replacement: while a candidate prepares or is in probation, cycles run one at a time on the serial path, so cut-over and rollback keep their exact semantics. Live edits and pause apply at the next quiesce point. |
| On a failure, the run stops | The failing stage marks the run's end cycle **before** routing anything else: no node downstream of the failure sees a later cycle, and earlier cycles complete. Branches independent of the failed node may have run up to their queue depth ahead (inherent to pipelining). |

### Throughput (Apple M4, release, 6 MB numpy frames, 600 cycles)

| graph | mode | cycles/s |
|---|---|---|
| `packages/bench/rust-pipeline-numpy.yaml` | serial | 412.1 |
| same | pipelined | 429.1 |
| `packages/bench/rust-pipeline-numpy-parallel.yaml` (4 instances) | pipelined, derived arena | 702.8 (**1.71×** serial) |

The two-stage pipeline gains little, because the source's 6 MB arena publish (one counted copy per
frame) is the remaining serial step. The .NET reference measured 2.36× at 4 instances against its
own, slower, serial baseline. A compute-bound node scales almost linearly:
`parallel_instances_share_the_work_keep_order_and_raise_throughput` (four 20 ms Python instances)
needs well under 0.6× the serial time.

## Semantics to know

- **Scripted updates.** In pipelined mode, a plan step lands at the first quiesce point after it
  is submitted, not exactly "before `atCycle`". For example, a replacement requested for cycle 20
  starts at cycle 21. Each change is still atomic at a cycle boundary.
- **Quiesce cost.** Checkpoints stall the pipeline at every epoch (drain, capture, refill), as the
  .NET epoch barrier does.
- **Replication.** Replicated instances are rebuilt on restart without state. That is safe because
  `maxParallelism > 1` asserts the node keeps no state, and the contract forbids it for `stateful`
  nodes.
- **GPU in pipelined mode.** Device payloads cross stage threads in the same process, and the same
  device context applies. The GPU P0 run was measured serially (stage 10).
