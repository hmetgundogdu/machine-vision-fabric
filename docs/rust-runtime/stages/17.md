# Stage 17 — Network Fabric, part 2: source workers, FTP camera PoC, listener handover (#23)

**Status: PASS on Linux.** Measured on the Linux test host: privileged `debian:bookworm-slim`,
runc 1.1.5, iproute2, nftables, linuxkit 6.10 aarch64, no Python and no Docker daemon. Windows and
macOS restricted networking: **BLOCKED** (see [ADR-0003](../adr-0003-network-fabric.md)).

## What was built

- **Source workers (protocol v1 extension).**
  - A worker contract with no input and one frame output is capability `source`.
  - `execute` carries only an output slot. The child returns the frame (`cameraId`, `sequence`)
    or `exhausted`.
  - Python SDK: `run_source(module_id, produce)` and `source_frame(bytes, camera_id, sequence)`.
  - Documented in `protocol/README.md`.
- **`py.ftp-source`** (`modules/py-ftp-source`): a passive-mode FTP server, stdlib only, whose
  uploads become frames.
  - The camera id is the FTP user.
  - Config: `port`, `passiveRange`, `user`/`password`, `maxFiles`.
  - PASV replies advertise `MVF_ADVERTISE_IP`.
  - Control connections set `TCP_NODELAY`. Without it each transfer waited about 40 ms for the
    client's delayed ACK.
  - The node logs its peak RSS and CPU time when its stream ends.
- **Listener handover on live replacement.** Host-port leases belong to the pipeline node.
  - A successor generation starts *standby*: filter in place, DNAT not published.
  - `NodeHandle::promote` runs at cut-over and hands the listeners over in one atomic nftables
    batch.
  - A rollback promotes the restored generation back.
  - Only the publishing generation releases a lease.
  - A failed handover rejects the candidate, and the active generation keeps serving.

### Listener handover with concurrent clients

A client in `ext1` opened a new connection every 15 ms during the run. The node answers its
version.

```text
replies: err*12 v1*110 v2*176 v3*15 err*3 v2*187 err*7
  Promoted     cycle 170  cutover 19.8 ms   [lst g2] network: promoted, new connections reach 10.89.0.6 (handover 19.7 ms)
  Committed    cycle 190
  Promoted     cycle 421  cutover  9.3 ms   [lst g3] promoted (handover 9.1 ms)
  RolledBack   cycle 440  cutover  2.3 ms   [lst g2] promoted (handover 2.2 ms)   [replace.candidate-failed]
```

What the trace shows:

- The leading `err*12` is the time before v1's server listens.
- **v1 → v2 is seamless for new connections:** no failed connection between them.
- v3 crashed on its 20th frame. `err*3` is the window between the crash and the rollback. Then v2
  takes the port back and serves until the run ends; the trailing `err*7` comes after shutdown.
- Connections established with a previous generation keep working until that generation stops.

The cut-over pause now includes the `nft` invocation, 2–20 ms. It was ≤ 1 ms in the P0 runs, which
had no network. A netlink implementation would remove the process spawn (ADR-0003).

### Cost: native worker vs OCI `restricted` (same Linux VM/kernel, 20 × 256 KiB uploads, FTP round trip per file)

| | p50 | p95 | p99 | throughput | node peak RSS | node CPU | copies into the graph |
|---|---|---|---|---|---|---|---|
| native worker, host network, loopback client (`rust:1.95-bookworm`) | 0.21 ms | 0.30 ms | 0.34 ms | 1102 MiB/s | 16.2 MiB | 0.018 s | 0 |
| OCI `restricted`, LAN client through bridge + DNAT + nftables (test host) | 0.24 ms | 0.41 ms | 0.57 ms | 955 MiB/s | 20.3 MiB | 0.053 s | 0 |
| native worker on macOS (loopback, for reference) | 0.45 ms | 0.52 ms | 0.53 ms | 558 MiB/s | 16.9 MiB | 0.055 s | 0 |

The enforced path costs about 15 % throughput and a slightly wider tail. Part of the gap is the
different client paths: a namespace over a bridge versus loopback. Network reception itself is not
zero copy; the copy count is for the graph side.

## Limits

- The .NET engine does not host source workers. Only the Python SDK has `run_source`.
- The FTP module is a PoC: STOR, PASV and simple authentication; no TLS (FTPS), EPSV or active
  mode. It is for authorized, isolated test networks only.
- A long-lived connection is cut when the generation serving it stops. That happens at commit, or
  when a crashed candidate is rolled back.
- The limits of [stage 16](16.md) still apply: IPv4 only, no multicast, no rootless, Windows
  BLOCKED.
