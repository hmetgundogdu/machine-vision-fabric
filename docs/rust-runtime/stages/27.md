[Stage 26](26.md) staged packages on the strength of the digests an operator declares and of who
may upload. This stage adds the case where packages come from a build system and the edge box
must check who built them.

## What was built

- **Policy in the runtime** (`mvf_management::upload`):
  - With `UploadOptions::trusted` keys (`mvf-rs run --manage --allow-uploads --trust-signer
    KEY|FILE`, repeatable), `stage` requires a signature by one of them.
  - **What is signed:** Ed25519 over a versioned line format, the package name and every file's
    SHA-256 sorted by path (`signing_bytes`). Names cannot contain spaces or newlines, so the
    format is unambiguous.
  - **Refusals:**
    - `unsigned`;
    - `untrusted-signer`;
    - `bad-signature`: files changed after signing, signed for another name, or a malformed
      signature.
  - The files stay uploaded after a refusal, so a correct signature can still stage them.
  - **Kept:** the signature is stored as `signature.json` beside `manifest.json`; the reply and
    the audit say `signedBy`.
  - Re-staging stays idempotent.
  - A malformed trusted key stops the runtime from starting.
  - `--trust-signer` without `--allow-uploads` is refused.
- **Verification** uses `ed25519-dalek` 2.2 (`verify_strict`), pure Rust: the runtime gains no C
  crypto.
- **Signing** (`mvf-remote sign`, with the `ring` it already has):
  - `keygen --dir D` writes `signer.pk8` (PKCS#8, 0600, never overwritten) and `signer.pub`
    (`ed25519:<hex>`, the id runtimes trust);
  - `package --key K --package P --out F DIR` writes `{package, key, sig, files}`.
- **Uploading signed:** `--signature F` on `mvf-rs manage upload` and on `mvf-remote upload`
  (`upload_dir_signed`).

## Limits

- **Trusted keys are configured per run** (`--trust-signer`). There is no key distribution or
  rotation service: replace the key and restart, as with any start-up setting.
- **No revocation list for signing keys,** and no expiry inside a signature. Removing a key from
  `--trust-signer` revokes it for the next start.
- **The signing key's protection is the builder's job.** `signer.pk8` is mode 0600, and an HSM
  or KMS is out of scope.
- **A signature covers the package, not its activation.** Who may `replace` is still the
  operator role, and it is audited.
