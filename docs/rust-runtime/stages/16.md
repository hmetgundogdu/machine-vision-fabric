**Status: PASS on Linux** (test host: privileged `debian:bookworm-slim`, runc 1.1.5, iproute2,
nftables, linuxkit 6.10 aarch64). Windows (HNS/WFP) and macOS: **BLOCKED**, documented below.

## What was built

**Contract** (`spec.permissions.network`, portable): either a bare mode (`none` (default),
`loopback`, `host`, `restricted`) or restricted rules:

```yaml
permissions:
  network:
    mode: restricted
    inbound:
      - { protocol: tcp, port: 2121, source: 192.168.1.10/32 }
      - { protocol: tcp, portRange: 50000-50100, source: 192.168.1.10/32 }
    outbound:                      # or `deny` (default)
      - { protocol: tcp, destination: 10.0.0.5/32, port: 502 }
```

Validation:

- rules need `mode: restricted`;
- `restricted` needs `isolation.minimum: sandbox`;
- each inbound rule has exactly one of `port` or `portRange`;
- port ranges must be well formed (at most 4096 ports);
- source and destination CIDRs must be valid (IPv4 or IPv6).

Codes: `contract.permissions.network-rules-need-restricted`, `contract.isolation.needs-sandbox`,
`contract.permissions.invalid-port`, `contract.permissions.invalid-cidr`.

**Deployment binding** (operator side, per pipeline node, not part of the portable contract):
`network: { hostIp, ports: [{ protocol, port, hostPort }], advertise }`. A binding may only
publish ports the contract declares (`graph.network.unbound-port`). Addresses are checked
(`graph.network.invalid-address`). `advertise` reaches the node as `MVF_ADVERTISE_IP`, for example
for passive FTP replies.

**Negotiation, with honest labels:**

| Backend | `none` / `loopback` | `host` | `restricted` |
|---|---|---|---|
| OCI (sandbox) | `none` enforced: empty namespace | the host network, with a `placement.host-network` note | **enforced** when the host has root, `ip` and `nft`; otherwise rejected (`negotiation.permission-unsupported`) |
| worker / in-process (trusted) | **not enforced**: the node shares the host network, and the worker logs exactly that at start | the host network | **rejected** (`negotiation.network-not-enforceable`); a required policy fails closed |

**Linux enforcement** (`mvf_container::network`): a `restricted` node gets the following.

- Its own network namespace `mvf-<n>`, reached through a routed veth pair: `10.89.<n>.2/30`
  inside, `.1` on the host.
- The namespace is owned by the host's user namespace, so the node's root holds no capability
  over its interface and cannot change its address, routes or rules. As a consequence the node
  gets an empty `/sys` instead of sysfs.
- One nftables table per node, `inet mvf_<n>`:
  - **published listeners** are DNAT-ed from the host address and port to the node, only from
    the rule's `source`;
  - **inbound** traffic is accepted only to declared ports, everything else to the node is
    dropped;
  - **outbound** connections are allowed only to declared destinations and masqueraded behind
    the host, everything else is dropped;
  - the node can never reach the host itself;
  - **return traffic** of permitted sessions always flows (`ct state established,related`),
    including when new outbound connections are denied;
  - anti-spoofing: from the node's interface only the node's own address is accepted;
  - every rule kind is counted (`in-accept`, `in-deny`, `out-accept`, `out-deny`, `host-deny`,
    `spoof`); counters are logged when the node stops.
- **Ports.** Host ports are leased (`<state>/net/ports/<proto>-<port>`). A port published by
  another MVF node, or bound by any other process, makes the node fail at start with an
  actionable error.
- **Cleanup.** Stop, crash and error paths remove the table, interface, namespace and leases.
  Leases left by a dead host process are swept before the next allocation.
- **Effective policy.** One supervisor log line per node, for example
  `network: restricted ip=10.89.0.2 inbound=[tcp 0.0.0.0:2121 -> 2121 from 192.168.77.10/32]
  outbound=[deny] (default deny; return traffic allowed)`. No credentials ever appear in it.

Normal network traffic never touches the graph data plane, and there is no user-space proxy:
the kernel routes and filters.

## Limits

- **Addressing and discovery.** Only IPv4 is supported: IPv6 rules are rejected, and the node
  has no IPv6 address, so there is no v6 connectivity. Broadcast and multicast (for example
  camera discovery) do not cross the routed veth; such nodes need `host` mode for now. Multiple
  NICs and VLANs are reachable through `hostIp` publishing, but the node has one interface.
- **Host-local clients.** Clients on the host itself reach a published node at its node address,
  not at `127.0.0.1`/hostIp (there is no `output`-hook DNAT).
- **Privileged ports.** Ports below 1024 cannot be bound inside the node: no capability is
  granted. Publish a high node port on host port 21 with the binding.
- **Live replacement.** Resolved in part 2 ([stage 17](17.md)): a successor generation of the same
  node shares the lease, starts standby and is promoted at cut-over. A port held by another node
  still fails closed.
- **Rootless.** Restricted networking needs root (#27 tracks rootless OCI).
- **Windows: BLOCKED.** HNS/HCS and Windows Filtering Platform enforcement are not implemented and
  there is no Windows host with containers. On Windows, trusted nodes share the host network and
  `restricted` is rejected.
- **macOS.** Native nodes share the host network (documented). Linux OCI needs a VM, which is not
  in scope.
