[Stage 26](26.md) took previews from the serial executor only. A pipelined run (`--mode
pipelined`) could be watched but never previewed. This stage closes that gap.

## What was built

- **Sources** run on the pipelined driver thread, which owns the observer. They are sampled
  exactly as in the serial executor: asked per execution, outputs handed over at once.
- **Mid-graph nodes** run on their own stage threads, which cannot call the observer:
  - Once per cycle, the driver asks `wants_outputs` for each stage that has no sample in flight.
    On `true` it sets that node's flag (an `AtomicBool`).
  - After its next execution, the stage clears the flag and sends those outputs (shared leases,
    not copies) as a `StageEvent::Outputs` on the event channel it already uses for node events.
    The driver passes them to `Observer::outputs`.
  - Replicated stages (`parallelism > 1`) sample when results are re-ordered by cycle, so a
    sample is always the node's output for the cycle it names.
  - **Cost and bounds:** a stage never waits for this, and at most one sample per node is in
    flight. An unarmed stage pays one relaxed atomic load per execution.
- **`Observer` contract** (`crates/mvf-engine/src/executor.rs`): each `true` from
  `wants_outputs` asks for one `outputs` call for that node. In the pipelined executor other
  nodes' calls may come in between. None arrives if the node does not execute again before the
  run ends or stops at a boundary.
- **`Tee`** (`crates/mvf-management/src/feed.rs`) now counts what each of its two observers asked
  for, per node. It used to remember only the last answer, so in a pipelined run a later
  question about another node would have discarded the first observer's sample.
- **Arena headroom** (`mvf-rs run --mode pipelined --preview …`, when the arena is sized from
  the graph): one slot per previewed node plus two. That covers a sampled frame in transit to
  the driver, one queued for the preview thread and one being downscaled, so previewing never
  makes a publisher stall or drop.

## Limits

- **A mid-graph preview may trail the source by the queue depth.** It shows the node's next
  execution after the driver asked, and carries the cycle it shows.
- **Sampling is a request, not a schedule.** If a node stops executing (an untaken branch, a run
  stopped at a boundary), its armed sample never arrives, and the observer is not told.
- **No measurements on industrial edge hardware.**
