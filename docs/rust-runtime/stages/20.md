**Status:**

| Combination | Result |
|---|---|
| Linux OCI (runc, no Docker daemon), measured on the Linux test host | **PASS**, enforced |
| Workers on macOS and Linux | **PASS**: provisioned, not isolated, and labelled so |
| Windows | lint clean; CI runs the portable tests |

## What was built

- **Contract.**
  - `spec.storage.mounts[]`: `name`, `target`, `access`, `kind: volume|scratch`, `maxSize`,
    `required`.
  - `spec.storage.isolation: best-effort|required`.
  - Validation: safe, normalized, non-overlapping targets outside the reserved sandbox and system
    paths; sizes; read-write scratch.
- **Negotiation.** `BackendCapabilities.storage` has `mounts`, `enforced` and `hard_quota`:
  - OCI: true / true / true;
  - worker: true / false / false;
  - in-process: none.
  - Codes: `negotiation.storage-not-enforceable` and `-unsupported`; note
    `placement.storage-not-isolated`.
- **Pipeline.**
  - `spec.volumes[]` declares `persistent`, `shared` (with `writers`), `bind` (`hostPath`, max
    `access`) and `artifact` (`file`, `digest`) volumes.
  - A node binds them with `storage: { mount: volume }`.
  - `mvf_graph::bind_storage` gives each mount the access it asked for, never more than the
    volume allows. It is used at build and for replacement rebinding.
- **`mvf-storage`.**
  - Provisioning of all volume types and of scratch (a host directory for workers, a tmpfs for
    sandboxes).
  - Host-path policy: deny list, symlink-free canonical form, no home directory. Read-write binds
    are checked against the sandbox uid.
  - Artifact import into its own content store: verified, read-only, deduplicated. Each
    generation gets a read-only view.
  - Per-run directories with a crash sweep; listing, usage and explicit delete.
- **Backends.**
  - Workers get `MVF_VOLUME_<NAME>` host paths; scratch and views live as long as the generation.
  - OCI nodes get kernel binds (`ro`/`rw`, `nosuid,nodev,noexec`) and `size=` tmpfs, with
    `MVF_VOLUME_<NAME>` set to the target. Managed directories are chowned to the mapped uid.
    Mount targets are created in the rootfs and refused if the image redirects them.
- **Live replacement.** `ReplacementRequest::with_storage` (and `storage:` in update plans)
  rebinds mounts, for example to a new model. It is validated up front
  (`replace.storage-invalid`); rollback restores the old bindings.
- **Python SDK:** `mvf_sdk.storage.volume(name)` and `write_atomic(path, data)`.
- **`modules/py-model-inspector`:**
  - Reads `*.onnx` from `model`, checks its SHA-256 and parses the ONNX header (IR version,
    producer, opset).
  - Publishes one record per frame into `results` and writes a work file into `tmp`.
- **CLI:** `mvf-rs volume list [--json] | inspect <pipeline>/<volume> | delete <pipeline>/<volume> --yes | artifacts`.

- **Worker vs OCI `fsync` numbers:** they come from different containers on the same VM. Read
  them as the variance of `fsync` on overlayfs, not as a bind-mount cost: a bind exposes the same
  inode and adds no layer. macOS `fsync` does not force a platter flush (`F_FULLFSYNC` would).
- **Disk usage:** shown by `mvf-rs volume list` (bytes, files). Artifacts are stored once
  (`volume artifacts`).

## Limits

- **Workers are not confined.** Read-only artifacts are protected by file permissions only, and
  root bypasses them. Scratch sizes are advisory. `isolation: required` is how a node demands a
  sandbox.
- **A volume's size is its filesystem's:** there are no project quotas on persistent volumes.
  Free space is checked for worker scratch.
- **Rooted OCI only** (#27 for rootless). A read-write host bind must already be writable by the
  sandbox's mapped uid; MVF does not chown operator directories.
- **Artifacts are single files.** Directory artifacts (tarballs) are a later step. Cached blobs are
  re-verified only with `MVF_STORAGE_VERIFY=always`.
- **Rollback does not version mutable volumes.** What a failed candidate wrote stays written.
- **Container pids are namespace-local** (every process is pid 1), so records must not be named
  by pid. The inspector uses a per-process run id.
