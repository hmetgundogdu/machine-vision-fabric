# Stage 09 — GPU-native compute and device-resident zero-copy proof (#19)

**Status: PASS on Apple M4 / Metal (local hardware) · cross-process GPU sharing not implemented
(documented) · no GPU in CI (hardware tests report `NOT RUN` there)**

## Choice of API (primary sources: wgpu 30 docs/source, WGSL spec)

`wgpu` 30.0.2 with WGSL kernels: one portable compute API over Metal (macOS), Vulkan (Linux,
Windows) and DX12 (Windows), safe Rust, no vendor SDK. CUDA was not chosen for the first backend
because the only hardware available for real execution is an Apple GPU, and Windows-first edge PCs
commonly ship Intel/AMD iGPUs; a CUDA/TensorRT backend can sit behind the same `ExecutionBackend`
seam later. WGSL division is allowed up to 2.5 ULP error, so GPU and CPU results are compared with
an error bound, not bit for bit.

## What was built (`rust/crates/mvf-compute`)

- **Device payloads in the engine**: `PayloadData::Device(Arc<dyn DeviceBuffer>)` next to heap and
  arena payloads. Host bytes of a device payload only exist after an **explicit, counted**
  download (`Payload::try_bytes`); device-native consumers use the handle. The executor counts
  `deviceDeliveries` separately from heap/arena deliveries.
- **`GpuContext`** — one logical device: adapter identity (`wgpu:<backend>:<name>:<vendor>:<device>#n`),
  hardware-only by default (a software rasterizer is refused), buffer allocation within a software
  memory budget (wgpu has no portable VRAM quota), counted uploads/downloads/hand-offs/dispatches,
  allocation accounting released on drop.
- **Kernels** (`kernels.rs`): `invert-u8`, `normalize-u8-f32`, `mean-f32` (workgroup reduction
  to 64 partial sums). Bytes are packed into `u32` words, a uniform carries the logical length
  (padding never leaks into results), dispatches switch to 2-D past the per-dimension limit.
- **`ComputeBackend`** (`backend: compute, api: wgpu`): isolation `none`, targets `[gpu]`,
  zero-copy domain `device`, cooperative cancellation (checked before each dispatch). A compute node
  takes a same-device input **by handle** (counted hand-off); an input on another device or in host
  memory is an explicit transfer — refused with `Unsupported` when the contract requires zero copy.
- **Synchronization**: all nodes of a context submit to one queue; wgpu executes a queue's
  submissions in order, so a consumer's dispatch observes its producer's writes without extra
  fences. Host reads wait for the queue (`map_async` + `poll(Wait)`). No cross-queue or cross-device
  synchronization is attempted.
- CPU reference builtins `normalize-u8-f32`, `mean-f32`; example graphs `rust/examples/gpu/`
  (`pipeline.yaml` GPU chain, `pipeline-cpu.yaml` the same graph on CPU, node contracts incl. a
  GPU-or-CPU fallback contract). The CLI registers the compute backend when a hardware adapter
  exists (`MVF_DISABLE_GPU=1` to turn it off).

```text
GPU: Apple M4 | backend Metal | type IntegratedGpu      (macOS 26.6.2, wgpu 30.0.2, rustc 1.95.0)
$ MVF_REQUIRE_GPU=1 cargo test -p mvf-compute --release      # 8 passed
GPU chain: 100 frames of 307200 bytes; GpuMetrics { uploads: 100, upload_bytes: 30720000,
  downloads: 100, download_bytes: 25600, device_handoffs: 200, dispatches: 300, allocated: 0,
  peak_allocated: 1536256 }
```

**Device-resident path**: per frame exactly one host→device upload (the camera is a CPU source),
two device hand-offs by handle (invert→normalize, normalize→mean), three dispatches, and one
**compact** device→host transfer of 64 partial sums (256 bytes) — never the frame or the f32
tensor. All device memory is released after the run.

## Limitations

- **Cross-process GPU sharing is not implemented**: device buffers are shared between in-process
  compute nodes of one context. Handing a GPU buffer to a worker or OCI node would need IOSurface/
  `MTLSharedEvent` (macOS), CUDA IPC or Vulkan external memory; such contracts are rejected
  (workers and OCI nodes only offer host-memory zero copy). DLPack is not used as IPC.
- One logical device per backend instance; no multi-GPU placement, no cross-vendor sharing.
- No GPU in CI: the hardware tests skip there with a visible `NOT RUN` line; the recorded results
  above are from local hardware.
- The memory budget is a software accounting limit, not a driver-enforced VRAM quota.
- Kernels are trusted, in-process code (isolation `none`).
